# پروژه بانک اطلاعات ECU خودروهای ایرانی v6.0

## هدف
ساخت مرجع مهندسی جامع، دقیق و صنعتی از اطلاعات ارتباطی و رمزگشایی ECU تمام خودروهای ایرانی، قابل استفاده در طراحی و توسعه تجهیزات و نرم‌افزارهای تخصصی خودرو.

## معماری
- **Go (خزنده وب)**: پیمایش بازگشتی سایت SICAR، دانلود موازی صفحات و فایل‌ها، استخراج اولیه داده، مدیریت همزمانی و rate limiting
- **Python (پردازش و تحلیل)**: بارگذاری داده، استخراج از GitHub، جست‌وجوی چندلایه، مدیریت تعارضات، تولید خروجی‌های نهایی

## دامنه منابع داده‌ای

| سطح | منبع | نوع داده |
|-----|------|----------|
| 💎 Diamond | اسناد رسمی کارخانه (PDF/Excel) | بالاترین اعتبار |
| 🏆 Primary | وب‌سایت SICAR (ecu.sisoog.com) | منبع اصلی |
| 🥇 Gold | مخزن GitHub Sisoog/sicar-diag | تأیید و تطبیق |
| 🥈 Silver | Reddit, Telegram, Kaggle | فقط سرنخ |
| 🥉 Bronze | Wikipedia, ISO/SAE | استانداردهای عمومی |

## نحوه اجرا

### مرحله ۱: خزیدن سایت با Go
```bash
cd go_crawler
go run main.go -out ../output/go_crawler -workers 6 -rate 350ms
```

پارامترهای Go:
- `-base`: آدرس پایه سایت (پیش‌فرض: https://ecu.sisoog.com)
- `-out`: پوشه خروجی
- `-workers`: تعداد thread همزمان (پیش‌فرض: 6)
- `-rate`: حداقل فاصله بین درخواست‌ها (پیش‌فرض: 350ms)
- `-max-pages`: محدودیت تعداد صفحه برای تست (0 = نامحدود)
- `-fresh`: شروع از صفر (نادیده گرفتن state قبلی)
- `-history=false`: غیرفعال کردن دانلود نسخه‌های قدیمی

### مرحله ۲: پردازش و تولید خروجی با Python
```bash
cd ..
python main.py --go-output ./output/go_crawler --out ./output/final
```

پارامترهای Python:
- `--go-output`: مسیر خروجی خزنده Go
- `--out`: مسیر خروجی نهایی
- `--diamond-dir`: پوشه اسناد رسمی کارخانه (سطح Diamond)
- `--offline`: حالت آفلاین (بدون دسترسی شبکه)
- `--skip-github`: رد کردن استخراج از GitHub
- `--skip-multi-tier`: رد کردن جست‌وجوی چندلایه
- `--skip-diamond`: رد کردن پردازش سطح Diamond
- `--skip-word`: رد کردن تولید مستندات Word
- `--refresh`: نادیده گرفتن کش
- `--limit N`: محدودیت تعداد رکورد برای تست

## خروجی‌های تولیدشده

### ۱. Excel جامع
- `ECU_Master_Database.xlsx`: بانک اطلاعات کامل با قابلیت فیلتر
  - شیت ECU_Data: تمام رکوردها با ۴۵ ستون استاندارد
  - شیت DTC: کدهای خطا
  - شیت Connection: مشخصات پروتکل و اتصال
  - شیت Summary: خلاصه آماری
  - شیت Sources: فهرست منابع
  - شیت Coverage_not_in_json: مواردی که فقط در جدول هستند
  - شیت Version_History: تاریخچه تغییرات فایل‌ها

### ۲. گزارش تعارضات
- `Conflict_Report.xlsx`: تمام موارد اختلاف بین منابع
- `conflicts.json`: نسخه JSON گزارش

### ۳. آرشیو JSON ساختاریافته
- `JSON_Archive/ECU_Hierarchy.json`: ساختار درختی
  ```
  Manufacturer → Vehicle → ECU → {
    connection: [...],
    init: [...],
    parameters: [...],
    dtcs: [...]
  }
  ```
- `JSON_Archive/originals/`: اصل فایل‌ها بایت‌به‌بایت

### ۴. مستندات Word مهندسی
- `Word_Docs/ECU_Engineering_<Manufacturer>.docx`: مستند به‌ازای هر خودروساز
- `Word_Docs/ECU_Engineering_Guide.docx`: راهنمای کلی

### ۵. گزارش‌های جانبی
- `pipeline_report.json`: گزارش کامل اجرا
- `rejected_records.json`: رکوردهای ردشده با دلیل
- `version_diff_run.json`: مقایسه با اجرای قبلی
- `multi_tier/silver_leads.json`: سرنخ‌های سطح Silver

## مدیریت تعارضات

وقتی دو منبع خروجی متفاوت می‌دهند:
1. هر خروجی جداگانه با ذکر منبع نگهداری می‌شود
2. درصد اطمینان هر مقدار محاسبه می‌شود
3. ترتیب بر اساس وزن سطح منبع (Diamond > Primary > Gold > ...)
4. در گزارش Conflict_Report.xlsx ثبت می‌شود
